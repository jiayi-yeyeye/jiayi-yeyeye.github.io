围绕原文完成理解、笔记与自测的 AI 阅读工具

读电子材料时，查一个术语就要切到另一个窗口。把解释抄进笔记，重读时还得找回原来那一段。我把查词、追问和批注放回同一页：读者可以圈选难点，先看简短解释，再把有用的那一版贴在原文旁。复习时，既能导出带标注的 PDF，也能围绕刚读过的内容做自测。

查看工作流 ↓打开阅读器

从原文出发，让理解留下来

先看阅读器如何连接材料、解释、笔记和自测。读者可以按需要进入不同路径，不必把每个步骤都做一遍。

产品决策
  • 围绕同一份文档组织解释、标注和测验，减少在不同材料之间重新建立关联。
  • 解释、做笔记与自测是可选分支，不把读者推入必须完成的流水线。
  • 保存与导出分别承担继续阅读和带走复习材料的用途。

ANALYTICS / DATA GOVERNANCE

EventFlow · 埋点与数据治理

B端事件规范审核发布数据质量
返回项目封面

做埋点验收时，报表里少了一次操作，很难仅凭数字判断是事件没收到、字段填错，还是测试数据进了正式环境。我从一次上报的去向入手，把事件定义、来源与环境校验、去重和接收回执串起来。产品和研发可以按回执定位拒收原因，再用通过校验的事件做分析；修改采集规则时，也能先验证候选版本再审核发布。

查看 SDK 如何生成与发送事件

EventFlow 的输入包括事件定义、采集规则和业务应用提交的事件包。平台将校验后的事件事实与接收回执分别保存，再由分析页面和验证页面读取。

产品决策
  • 事件事实与回执分别使用。 有效事件供统计，回执供检查每次处理结果，同一事件重试可能产生新的回执。
  • 可信环境信息由服务端核验。 我要求测试与正式数据分别归属，指定账号监测保留部署环境。
  • 质量问题保留独立处置入口。 管理员可以查看拒收原因并标记处理状态。

实现边界 图中回执表示逐事件处理结果。身份、来源或限流等请求级拒绝可能没有逐条回执。

让事件从采集入口进入可检查、可分析、可审核的数据流程。

SDK / VISUAL TRACKING

可视化埋点 SDK

B端可视化圈选AI 辅助配置运行时上下文
返回项目封面

同一个按钮会出现在多个标签页和多张卡片上。只记录“用户点了按钮”，既分不清操作的是哪条内容，也无法判断保存是否成功。我把控件圈选和业务字段绑定分开，让 SDK 在交互发生时读取当前实例；对新增批注这样的操作，则等保存成功再记录业务事件。随后用接收回执逐条核对预期与实际上报。

查看 EventFlow 如何校验、存储与使用数据

SDK 的输入包括已批准配置、页面交互和显式业务信号。规则解析器只提取配置允许的字段，补充必要标识后生成事件。知豆了适配层负责提供业务上下文与同源服务接口。

产品决策
  • 配置与执行分开维护。 管理员在 EventFlow 审核规则，SDK 在业务页面执行已取得的有效配置。
  • 业务适配提供必要语义。 控件、记录、页面和完成信号来自知豆了代码中的显式接入。
  • 不同标识承担不同用途。 事件类型用于分类，单次 ID 用于重试去重，规则 ID 用于关联配置。

实现边界 服务端业务结果还有知豆了适配层的 D1 发件箱路径。该能力属于接入应用服务端，SDK 浏览器包负责图中的客户端路径。

AI KNOWLEDGE / PERSONAL WORKSPACE

Folia｜个人知识收藏

C端对话入口原文证据实时延伸阅读
返回项目封面

让收藏长成知识

在不同平台点过收藏后，我常常只记得看过一篇文章，却想不起存在哪里。各平台的收藏夹需要手动分类，链接、截图和文件分散得越久，越容易被遗忘。我给 Folia 设计了统一的收藏入口：它读取可用原文，按用户选择的分类方式整理，拿不准的归属留待确认。下次即使忘了标题，也能用问题找回带出处的原文，或沿图谱重新发现相关收藏。

从一条收藏，到可以找回的知识

用户通过对话保存链接与文字，或上传文件。系统保留来源和读取范围，结合用户选择的分类方式提出整理结果。保存后的内容可以用于原文问答、日常维护和图谱浏览。

产品决策
  • 让读取状态和原文一起可见，部分读取也要交代缺失范围。
  • 将分类建议、用户确认和保存结果分开，只有提交成功才更新收藏视图。
  • 离线保存使用本机库，登录后经用户确认导入云端。

实现边界 已实现路径，采集能力为部分覆盖。真实平台读取成功率、邮件送达与长期使用效果待验证。

离线路径独立播放；提交失败单独展示。末尾问答和图谱是可选用途，不表示系统自动执行。

返回项目封面

从企业数据到人工决策与跟进

打开总览、更新报告均不会自动触发联网 Agent；外部环境展示最近一次 Agent 结果。支持方案确认后的资源安排与服务执行由人员完成。
