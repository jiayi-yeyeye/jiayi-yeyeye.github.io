An AI reading workspace for understanding, annotation, and self-assessment

Readers select a passage, start with a short explanation and pin the version that helps beside the original. They can revisit it in an annotated PDF or test themselves on what they just read.

02

ANALYTICS / DATA GOVERNANCE

EventFlow · Event Tracking & Data Governance

B2BEvent specificationsRelease reviewData quality
Back to project covers

When an action was missing from a dashboard, the count alone could not tell me whether an event was lost, a field was invalid or the test ran in the wrong environment. I traced a single submission through its definition, source checks, deduplication and receipt. Teams can inspect why an event was rejected, analyze validated events and test proposed rule changes before approving them.

See how the SDK creates and delivers events

EventFlow receives event definitions, tracking rules, and event batches from connected applications. Validated event facts and collection receipts are stored separately, then read by analytics and verification views.

PRODUCT DECISIONS
  • Use event facts and receipts for different purposes. Valid events support analytics; receipts describe processing attempts. Retrying an event may produce another receipt.
  • Verify environment information on the server. I required staging and production data to remain separate, including during account monitoring.
  • Provide a dedicated path for quality issues. Administrators can inspect rejection reasons and update issue status.

Scope & limits Receipts in this diagram represent per-event results. Request-level rejection, including authentication, origin, or rate-limit failures, may produce no per-event receipts.

Turn incoming events into inspectable, analyzable data governed by reviewable rules.

03

SDK / VISUAL TRACKING

Visual Event Tracking SDK

B2BVisual selectionAI-assisted configurationRuntime context
Back to project covers

The same button appears on multiple cards and tabs. A click alone tells us neither which item was involved nor whether a save succeeded. I separated visual element selection from business-field binding so the SDK reads the active instance at interaction time. For actions such as adding an annotation, it records completion after the save succeeds. Receipts let a reviewer compare the expected event with what actually arrived.

See how EventFlow validates, stores, and uses data

The SDK receives approved configuration, interface interactions, and explicit business signals. Its rule resolver extracts configured fields and adds required identifiers to create events. The Mewreka integration supplies business context and same-origin endpoints.

PRODUCT DECISIONS
  • Maintain configuration separately from execution. Administrators review rules in EventFlow; the SDK executes valid configuration in the app.
  • Let the app integration provide business meaning. Controls, records, pages, and completion signals are explicitly exposed by Mewreka.
  • Use identifiers for distinct purposes. Event types classify activity, occurrence IDs support retry deduplication, and rule IDs link events to configuration.

Scope & limits Server-side business outcomes also use a D1 outbox in the Mewreka integration. That capability belongs to the application backend; the browser SDK handles the client-side path shown here.

Convert interface interactions and business outcomes into structured events with explicit context.

AI KNOWLEDGE / PERSONAL WORKSPACE

Folia | Personal Knowledge Library

B2CConversational interfaceSource evidenceFurther reading
Back to project covers

Let your saved content grow into knowledge

I could remember reading an article long after I had forgotten which app I saved it in. Each platform had its own folders to sort by hand, and links, screenshots and files gradually slipped out of sight. I designed one place to collect them. Folia reads the available source, organizes it using the reader’s chosen scheme and leaves uncertain matches for review. Later, a question can lead back to a cited passage, and the graph can surface related saves.

From a saved item to knowledge you can revisit

Users save links and text through chat or upload files. Folia preserves sources and extraction coverage, then organizes content using the selected classification scheme. Saved material supports source-based Q&A, everyday library management and graph browsing.

PRODUCT DECISIONS
  • Show extraction status alongside source text, including what remains unavailable.
  • Separate suggestions, user confirmation and persistence. Update the library after a successful commit.
  • Use a device library for offline capture and an explicit import into the signed-in account.

Scope & limits Implemented paths with partial source coverage. Live extraction success, email delivery and long-term outcomes remain unverified.

Play the offline path separately and show commit failure as an alternate path. Q&A and graph browsing are optional uses, not automatic jobs.

CBIT Venture Builder — AI-Powered Portfolio Monitoring

B2BVenture monitoringEvidence agentHuman decisions & audit
Back to project covers

A shorter cash runway, a stale financial report and a change in market conditions can all put a startup on a watchlist. Each calls for a different next step. I separated these signals so reviewers can trace a flag to its evidence, then examine the agent’s sources and uncertainties. A reviewer sets the final attention level, selects support and records the rationale and outcome for the next review.

From company data to human decisions and follow-up

Connect data collection, monitoring, evidence review, human decisions and action records around periodic company updates. People update the data and trigger analysis as needed for the next review cycle.

Opening the overview or updating reports does not automatically run the web-enabled agent. External context reflects the latest agent result. People arrange resources and deliver services after confirming support options.
